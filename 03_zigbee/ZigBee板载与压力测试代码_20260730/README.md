# ZigBee 板载代码与压力测试代码总结

## 1. 内容说明

本包整理了 CC2530 ZigBee 终端的板载带宽测试代码、可直接烧录的固件、PC 端压力测试脚本和一组实测结果。板载端基于 TI Z-Stack 3.0.1 的 `SampleSwitch` 工程，PC 端通过 E180 网关的 TCP 数据端口接收并统计测试帧。

## 2. 目录结构

```text
板载代码/
  Source/                         应用层源代码
  IAR工程/                        IAR 工程文件
  固件/                           已编译 HEX 固件
压力测试代码/
  zigbee_bandwidth_tester.py      TCP 接收与带宽统计脚本
  示例结果/                       CSV 逐帧记录与 JSON 汇总
```

## 3. 板载代码总结

### 3.1 核心文件

- `Source/zcl_samplesw.c`：初始化、事件循环、组网恢复、传感器/测试帧发送、按键切换速率、LCD/OLED 状态显示、串口透传和下行控制。
- `Source/zcl_samplesw.h`：端点、事件和应用接口声明。
- `Source/zcl_samplesw_data.c`：ZCL 属性和端点描述。
- `Source/OSAL_SampleSw.c`：OSAL 任务注册。
- `IAR工程/SampleSwitch.ewp`、`SampleSwitch.eww`：IAR Embedded Workbench 工程入口。

### 3.2 带宽测试工作方式

板载程序通过 `SENSOR_REPORT_EVT` 周期发送测试帧，目标为协调器短地址 `0x0000`、端点 `0x01`，使用 EBYTE 厂商自定义 Cluster `0xFC08`。发送函数为 `AF_DataRequest()`。

按键 `HAL_KEY_SW_6` 用于循环切换测试档位：

| 档位 | 发送周期 | 理论帧率 |
|---:|---:|---:|
| 0 | 1000 ms | 1 帧/秒 |
| 1 | 500 ms | 2 帧/秒 |
| 2 | 200 ms | 5 帧/秒 |
| 3 | 100 ms | 10 帧/秒 |
| 4 | 50 ms | 20 帧/秒 |
| 5 | 20 ms | 50 帧/秒 |
| 6 | 10 ms | 100 帧/秒 |
| 7 | 暂停 | 0 |

屏幕显示当前档位、发送周期、序列号和网络/发送状态。终端未入网时显示 `NET:OFFLINE`；发送成功显示 `NET:TX OK`；失败时显示返回状态码。

### 3.3 应用负载格式

测试帧在 5 字节 ZCL 头之后携带 32 字节应用负载：

| 偏移（应用负载内） | 长度 | 含义 |
|---:|---:|---|
| 0 | 1 | 标记 `0xB0` |
| 1 | 1 | 协议版本 `0x02` |
| 2 | 1 | 终端 ID，当前为 `0x01` |
| 3 | 1 | 带宽档位 |
| 4 | 2 | 发送周期，毫秒，小端序 |
| 6 | 4 | 32 位连续序列号，小端序 |
| 10 | 2 | `AF_DataRequest` 接收计数 |
| 12 | 2 | 协议栈拒绝计数 |
| 14-31 | 18 | 填充数据 |

序列号用于计算丢帧、重复帧和乱序帧；接收/拒绝计数用于区分无线链路丢失与本地协议栈发送失败。

### 3.4 其他板载功能

- 使用 BDB 完成入网和掉线重连。
- 支持 UART0 初始化、接收和回显。
- 支持 EBYTE 透明传输下行控制及控制确认。
- 通过 P0.2、P0.4 控制执行器状态。
- 保留标准 ZCL Basic、Identify、On/Off 等回调框架。

## 4. 压力测试脚本总结

### 4.1 功能

`zigbee_bandwidth_tester.py` 使用 Python 标准库实现，无需安装第三方依赖。主要功能：

- 连接 E180 网关 TCP 数据端口。
- 从字节流中提取以 `0x55` 开头的网关帧。
- 校验 XOR 校验和。
- 解析终端短地址、端点、Cluster、RSSI、档位、周期、序列号和发送计数。
- 按短地址与档位分别统计接收帧数、帧率、丢帧、重复、乱序、吞吐率和平均 RSSI。
- 使用滑动窗口计算观测峰值吞吐率。
- 输出 UTF-8 BOM 编码的逐帧 CSV 和 JSON 汇总。
- 按“丢包率低于阈值、帧数达到阈值、协议栈拒绝数为 0”判定最大稳定档位。

### 4.2 运行环境

- Python 3.10 或更高版本。
- PC 与 E180 网关网络可达。
- 网关工作在 TCP Server/数据透传模式。
- CC2530 终端已烧录本包固件并成功加入 ZigBee 网络。

### 4.3 使用示例

```powershell
python zigbee_bandwidth_tester.py `
  --host 192.168.3.7 `
  --port 8887 `
  --expected-short 0xB25B `
  --duration 600
```

常用参数：

- `--host`：网关 IP，默认 `192.168.3.7`。
- `--port`：网关 TCP 数据端口，默认 `8887`。
- `--expected-short`：只统计指定 ZigBee 短地址；传入空字符串可统计全部终端。
- `--duration`：测试时长，默认 600 秒。
- `--idle-timeout`：连续无有效测试帧时的自动停止时间，默认 120 秒。
- `--peak-window`：峰值吞吐率滑动窗口，默认 5 秒。
- `--maximum-loss-percent`：稳定档位允许的最大丢包率，默认 1%。
- `--minimum-stage-frames`：稳定性判定所需最少帧数，默认 20。
- `--output-dir`：CSV、JSON 输出目录。

建议从档位 0 开始，每个档位保持至少 30-60 秒，再按板载按键切换至下一档。测试结束后以 JSON 中的 `maximum_stable_stage` 作为稳定吞吐能力参考。

## 5. 已有测试结果摘要

示例结果采集于 2026-07-29，目标短地址为 `0xB25B`，有效测试帧 2623 帧。档位 0-6 均未观察到丢帧、重复帧、乱序帧或协议栈拒绝。

程序判定的最大稳定档位为档位 6：

- 配置周期：10 ms。
- 实际接收帧率：约 21.276 帧/秒。
- 应用层平均吞吐率：约 5446.574 bit/s。
- 网关帧平均吞吐率：约 8340.066 bit/s。
- 平均 RSSI：约 -60.14 dBm。

档位 5 与档位 6 的实际帧率基本相同，表明当前链路或网关转发能力在约 21.3 帧/秒附近达到平台。JSON 中档位 7 的单帧峰值没有统计代表性，不应用作有效吞吐结论。

## 6. 注意事项

- 烧录前确认工程目标为 `EndDeviceEB`，硬件型号和端点配置与现场一致。
- 若终端短地址发生变化，需要修改脚本的 `--expected-short` 参数。
- 压力测试应逐档进行，避免直接从低速跳到 10 ms 档导致难以定位瓶颈。
- CSV 用于逐帧复核；JSON 用于汇总结论。
- `AF_DataRequest` 返回成功表示协议栈接受发送请求，不等同于对端必然收到，因此需要结合序列号丢帧统计判断链路质量。
